# Supabase Historical Data Setup

This guide sets up free long-term historical storage for TSA wait times using Supabase.

## What You Get

- **Free tier**: 500MB storage (enough for years of wait time data)
- **Historical queries**: Average wait at 5am over past 30 days
- **Peak hours analysis**: Busiest hours per airport
- **Automatic backup**: Stored in PostgreSQL, no maintenance

## Setup (5 minutes)

### 1. Create Supabase Account & Project

1. Go to [supabase.com](https://supabase.com)
2. Sign up (free)
3. Create a new project
4. Wait ~2 min for deployment
5. Go to **Settings → API** and copy:
   - `Project URL` → `SUPABASE_URL`
   - `anon public` key → `SUPABASE_KEY`

### 2. Set Environment Variables

Add to your deployment (Render, Vercel, or local .env):

```bash
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-anon-key-here
```

### 3. Initialize the Database

Run once to create the table:

```bash
pip install supabase
python supabase_integration.py --init
```

Or manually create the table in Supabase SQL editor (Settings → SQL Editor → New query):

```sql
CREATE TABLE historical_samples (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    airport_code TEXT NOT NULL,
    checkpoint TEXT NOT NULL,
    wait_minutes REAL NOT NULL,
    source TEXT NOT NULL,
    lane_type TEXT DEFAULT 'STANDARD',
    captured_at TIMESTAMP WITH TIME ZONE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE INDEX idx_airport_time ON historical_samples(airport_code, captured_at);
```

### 4. That's it!

Data starts flowing automatically. Every 2 minutes when your collector runs, new wait times are stored in both SQLite (local) and Supabase (cloud).

## Usage

### Query Historical Average at 5am (past 30 days)

```bash
curl "https://yoursite.com/api/historical-average?airport=LAX&hour=5&days=30"
```

Response:
```json
{
  "airport": "LAX",
  "hour": 5,
  "days": 30,
  "avg_wait": 8.3,
  "description": "< 15 min",
  "timestamp": "2026-05-10T..."
}
```

### Get Peak Hours

```bash
curl "https://yoursite.com/api/peak-hours?airport=LAX&days=30&top=3"
```

Response:
```json
{
  "airport": "LAX",
  "days": 30,
  "peak_hours": [
    {"hour": 17, "avg_wait": 28.5, "samples": 42},
    {"hour": 16, "avg_wait": 25.2, "samples": 40},
    {"hour": 18, "avg_wait": 23.1, "samples": 39}
  ],
  "timestamp": "2026-05-10T..."
}
```

## In Code

```python
from supabase_integration import get_average_wait_at_hour, get_peak_hours

# Average wait at 5am for past 30 days
avg = get_average_wait_at_hour("LAX", hour=5, days=30)
print(f"LAX at 5am averages {avg} minutes")

# Top 3 busiest hours
peaks = get_peak_hours("LAX", days=30, top_n=3)
for peak in peaks:
    print(f"{peak['hour']}:00 averages {peak['avg_wait']:.1f} min")
```

## Frontend Integration (Optional)

Once you have the API endpoints, add to your site:

```javascript
// Show historical average at 5am
async function show5AmAverage(airport) {
  const resp = await fetch(`/api/historical-average?airport=${airport}&hour=5&days=30`);
  const data = await resp.json();
  console.log(`${airport} at 5am averages ${data.avg_wait} min`);
}

// Show peak hours
async function showPeakHours(airport) {
  const resp = await fetch(`/api/peak-hours?airport=${airport}&days=30&top=5`);
  const data = await resp.json();
  data.peak_hours.forEach(peak => {
    console.log(`${peak.hour}:00 - ${peak.avg_wait.toFixed(1)} min`);
  });
}
```

## Troubleshooting

### "SUPABASE_URL or SUPABASE_KEY not set"
Make sure you set both environment variables before running the app.

### "Table does not exist"
Run `python supabase_integration.py --init` to create the table.

### "Failed to store samples in Supabase"
This is non-blocking. Local SQLite storage continues to work. Check your keys are correct.

### Data not showing up?
1. Verify environment variables are set
2. Run `/api/historical-average` manually to check
3. Check Supabase project → Table Editor to see if rows are being inserted

## Data Retention

The free tier includes 500MB. TSA wait times are ~200 bytes per sample. With 14 airports × 30 samples/day, that's:

- 14 × 30 × 200 bytes = 84KB/day
- ~25MB per year
- **20 years of data on free tier**

## Cost

**Free forever** (unless you exceed 500MB, which would take 20+ years).

If you later want faster queries or more storage:
- Pro tier: $25/month for 10GB + faster compute
- But honestly the free tier is sufficient for TSA Tracker
